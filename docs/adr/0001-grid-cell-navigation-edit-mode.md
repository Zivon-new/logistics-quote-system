# ADR-0001：新建路线向导中网格单元格的"选中态/编辑态"导航模型

## 状态

已确认（Accepted）— 尚未实现

## 背景

"新建路线"向导（Step1路线信息、Step2货物信息、Step3代理方案）以及Excel导入后的人工核对流程（ExcelImport / ManualInput，复用Step3AgentsForm）中，部分表格（Step3的费用明细/整单费用/税率明细）已经实现了"方向键切换单元格"的Excel式导航。

但现有实现有一个明显问题：**无论单元格是否处于文本编辑状态，方向键永远触发"切换单元格"**。这导致用户在输入框中编辑文字、想用左右键移动光标时，焦点会意外跳到相邻单元格，体验比"完全不拦截方向键"更糟。

而在真正的Excel中：
- 单元格被**选中**但未进入编辑（未双击）时，方向键/Tab用于在单元格之间移动。
- 单元格进入**编辑态**（双击进入，或直接打字覆盖原内容）后，左右键用于移动文本光标，上下键无响应，Tab/Enter仍可提交并跳转。

此外，Step1（路线基本信息，纯`el-form`两列布局，无表格、无任何导航）和Step2（货物明细`el-table`，无任何导航）目前对方向键完全不拦截，原生行为即"移动光标"——与Step3的"全部拦截"形成了不一致的体验。

## 决策

在Step1、Step2（货物明细表）、Step3（费用明细/整单费用/税率明细三个表）统一实现"**选中态 / 编辑态**"两态导航模型，对常规向导流程和ExcelImport/ManualInput复核流程同时生效（共享组件）。

### 核心机制

使用单一共享的 `isEditing` 布尔状态（同一时刻只有一个元素能拥有焦点，因此单个标志即可）：

- **选中态（默认）**：单元格获得焦点时执行 `.select()`（全选文本）。↑ ↓ ← → / Tab / Enter 均触发"跳到相邻单元格"。落到新单元格后，重新回到选中态。
- **编辑态**：
  - ← → ：不拦截，交给原生文本光标移动（不做边界跨格回退）。
  - ↑ ↓ ：无响应（数字输入框的原生spin已由现有 `blockNumberInputSpin` 拦截）。
  - Tab / Enter：仍被拦截，提交当前值并跳到下一单元格，新单元格重置为选中态。
- **退出编辑态**：焦点变化（`focusin`）时自动复位为选中态，不提供Esc撤销（YAGNI）。
- 不引入新的视觉样式区分两态。

### 进入编辑态的三种触发方式（缺一不可，均采纳）

1. **双击单元格**（对齐Excel的标准操作）。
2. **在选中态下直接打字**（原生"覆盖全选内容"行为，自然进入编辑态——这是最高频的真实操作路径）。
3. **对已经拥有焦点的单元格再单击一次**（用于在已选中的文本中定位光标；若无此规则，会出现"视觉光标已移动但逻辑仍是选中态"的状态不一致）。

### 非文本控件的特殊规则

- **下拉选择框**（币种、货值币种等 `el-select`）：收起状态=选中态（方向键正常跳格）；展开下拉时=编辑态（方向键交给下拉自身做选项高亮，不拦截）。
- **单选框组**（"是否新品" `el-radio-group`）：**永远处于选中态**，方向键始终用于跳格，需 `preventDefault` 覆盖原生"方向键切换选中值"的行为；选项值只能通过点击改变。
- **日期范围选择器**（"交易日期" `el-date-picker type="daterange"`）：拆分为"开始日期""结束日期"两个独立单元格，文本编辑规则同上；日历面板展开时视为编辑态（同下拉框规则）。

通用规则：**"原生有展开态、且展开后用方向键做内部导航的控件（下拉/日期/自动完成）→ 展开即编辑态，不拦截方向键；没有展开态、但原生方向键会改变值的控件（单选组）→ 永远选中态，覆盖原生方向键"**。

### Step1 网格拓扑（新增导航，此前无）

Step1为固定的8个表单字段，按4行处理，行内格子数不均：

| 行 | 单元格（按序） |
|---|---|
| 1 | 起始地、途径地 |
| 2 | 目的地、交易日期-开始、交易日期-结束 |
| 3 | 实际重量、计费重量 |
| 4 | 总体积、货值、货值币种 |

- ↑ ↓：按"行内索引对齐"跳转，目标索引 = `min(当前索引, 目标行格子数-1)`。
- ← →：按行内顺序移动，到达行首/行尾后停止（不跨行环绕）。
- 第1行按↑、第4行按↓：无效果。
- **Tab**：与→职责不同——按行内顺序移动，但到达行尾时换到下一行行首（跨行环绕，对齐Excel"Tab永远线性前进"的习惯）；第4行最后一格（货值币种）按Tab：无效果。
- **Enter**：与↓规则一致（索引对齐跳到下一行）；第4行按Enter：无效果。
- **不自动新增行**（固定字段，与下方动态表格规则不同）。

### 动态表格的自动新增行（沿用Step3现有模式，扩展到Step2）

Step2货物明细表与Step3的三个表均为动态表格：在最后一行按 ↓ 或 Enter 时，自动调用对应的"新增一行"方法（如 `addGoodsDetail()`），新行第一个单元格进入选中态（聚焦+全选）。Step1因字段固定，明确不适用此规则。

## 备选方案

1. **仅修复Step3现有导航的编辑态问题，Step1/Step2维持现状（不拦截方向键）**——会导致三个Step的交互模型不一致（同一向导内，部分区域方向键跳格、部分区域方向键移动光标），用户体感割裂。**未采纳**。

2. **编辑态触发仅靠双击**（不支持"直接打字进入编辑"）——更贴近严格的Excel语义，但实际操作中用户更习惯"选中后直接打字覆盖"，强制要求双击会显著增加操作步骤。**未采纳**，但保留双击作为补充入口。

3. **Step1网格按像素位置（而非行内索引）做上下键映射**——在行格子数不均时更"几何对齐"，但实现复杂度高，且用户确认"行内顺序索引对齐"已经足够自然。**未采纳**。

4. **下拉框/日期选择器展开时仍拦截方向键（跳格优先于控件内导航）**——会导致用户无法用方向键在下拉选项/日历中导航，破坏这些控件本身的可用性。**未采纳**。

## 影响

**正面**：
- Step1/2/3三步操作体验统一，符合Excel心智模型，降低学习成本。
- "直接打字覆盖"作为主要编辑路径，无需额外学习双击操作；双击/二次单击作为光标定位的补充手段。
- ExcelImport/ManualInput复核流程与常规向导共享Step3AgentsForm，改动自动覆盖两条流程。

**需注意的实现复杂度**：
- Step1并非真实表格（`el-form` + `el-row`/`el-col`），需要单独构建"行列坐标→输入框引用"的映射，与Step2/Step3基于`tr`/`td`的DOM遍历方式不同。
- 单选框组（`<input type="radio">`）也满足`target.tagName === 'INPUT'`，在构建"同行可聚焦元素列表"时需要特殊处理，避免被当作独立的左右导航目标。
- 自动完成控件（`单位`列）需设置 `:trigger-on-focus="false"`：聚焦（包括通过导航获得焦点）不会展开建议下拉（`aria-expanded`保持`false`），方向键按"选中态"规则跳格；仅当用户开始输入时才触发建议列表展开，进入"展开=编辑态"。若误设为`trigger-on-focus=true`，聚焦即展开会导致方向键被拦截为下拉内导航，无法跳格。
